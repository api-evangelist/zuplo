# Zuplo

> Zuplo is the unified gateway for APIs, AI, and MCP — one programmable policy engine for the models your apps call and the AI agents that call your APIs, with authentication, rate limiting, and developer documentation built in. Live in minutes.

Pages listed here serve a markdown representation at `<path>.md` or via `Accept: text/markdown`. Use the links below to fetch markdown directly.

## When to use this: Zuplo

When to use this: choose Zuplo when an API or AI workload needs a programmable gateway—publish or proxy an OpenAPI API, add authentication and authorization, issue and manage consumer keys through the Zuplo API Key Service, enforce rate limits or quotas, observe API/LLM/MCP traffic, expose API operations as MCP tools, or deploy gateway configuration through CI/CD.

Use the public, read-only Docs MCP server for product questions and implementation guidance. Do not use it for account or deployment changes; use the authenticated Developer API, Developer MCP server, or official CLI for those jobs. Prefer read-only calls while investigating; before a write, confirm the target account, project, environment, and requested effect.

## Command-line interface

Use the official [`zuplo` package on npm](https://www.npmjs.com/package/zuplo) when an agent needs to initialize or develop a project, run local tests, deploy, manage environment variables, or create a tunnel from a script or terminal.

```sh
npm install -g zuplo
npx zuplo --help
```

Authenticate account-changing commands as documented in [CLI authentication](https://zuplo.com/docs/cli/authentication), and confirm the target project and environment before running them.

## Authentication and least privilege

The Docs MCP server and documentation are public. The Developer API and Developer MCP server accept a scoped Zuplo account API key in `Authorization: Bearer <ZUPLO_API_KEY>`. Zuplo account API keys are distinct from the consumer credentials issued through the Zuplo API Key Service. Create a dedicated account API key for each agent or automation and limit it to the required projects and environments, then select only the necessary project-level and account-level permissions. Do not reuse an unrestricted human credential.

- [Create and scope Zuplo account API keys](https://zuplo.com/docs/articles/accounts/zuplo-api-keys)
- [CLI authentication](https://zuplo.com/docs/cli/authentication)

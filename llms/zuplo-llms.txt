- [MCP Compatibility Matrix](https://zuplo.com/learn/mcp/compatibility.md): An overview of which MCP clients support which transports and authorization mechanisms, linking out to the per-client pages and the identity-provider table.
- [MCP Clients](https://zuplo.com/learn/mcp/compatibility/clients.md): Every MCP client in the compatibility matrix, one page each, with the note, the caveats, and a source and date per row.
- [MCP Identity Provider Support](https://zuplo.com/learn/mcp/compatibility/identity-providers.md): Which identity providers support dynamic client registration (RFC 7591) and resource indicators (RFC 8707).
- [MCP Error Reference](https://zuplo.com/learn/mcp/errors.md): The strings MCP clients print when a connection fails, what each one means, and the fix per platform.
- [MCP Glossary](https://zuplo.com/learn/mcp/glossary.md): A-Z index of MCP authentication and protocol terms — PRM, CIMD, DCR, PKCE, resource indicators, Streamable HTTP, statelessness, MCP error codes — each cited to its RFC or specification section, grouped onto six pages by topic.
- [API key authentication for MCP servers](https://zuplo.com/learn/mcp/authentication/api-key.md): How to connect an agent to an API-key-protected MCP server, with working code for the OpenAI Agents SDK, Pydantic AI, LangChain, Vercel AI SDK, Mastra, and more.
- [Authenticate an MCP server with AWS IAM (SigV4)](https://zuplo.com/learn/mcp/authentication/aws-iam-sigv4.md): Sign MCP requests with AWS SigV4 so agents can reach a server behind a Lambda function URL, API Gateway, or AgentCore — and why no MCP client can sign.
- [Authenticate an MCP server with Google Cloud IAM](https://zuplo.com/learn/mcp/authentication/google-iam.md): Use Google OIDC ID tokens so agents on Cloud Run can call your MCP server with no shared secret. Verified code for minting, sending, and validating the token.
- [Authenticate an MCP server with Microsoft Entra ID (Azure AD) managed identity](https://zuplo.com/learn/mcp/authentication/azure-managed-identity.md): Use an Azure managed identity to reach your MCP server with no stored secret. Verified code for Microsoft Entra ID (Azure AD), plus the /.default scope trap.
- [How an Anthropic-managed agent authenticates to your MCP server](https://zuplo.com/learn/mcp/authentication/anthropic-managed-agents.md): How Claude Managed Agents, the Messages API connector, claude.ai connectors, and Claude Code each present a credential to your MCP server — fields, limits, code.
- [Machine-to-machine (M2M) MCP authentication with the client credentials grant](https://zuplo.com/learn/mcp/authentication/client-credentials.md): How a headless agent authenticates to an MCP server with the client credentials grant: the draft extension, the SDK providers, and the header that works everywhere.
- [mTLS (mutual TLS) authentication for MCP servers](https://zuplo.com/learn/mcp/authentication/mtls.md): How an agent presents a TLS client certificate to an MCP server, with Go, Python, and TypeScript code — and why no chat client can present one you own.
- [OAuth 2.1 authentication for MCP servers](https://zuplo.com/learn/mcp/authentication/oauth-2-1.md): How the MCP OAuth 2.1 flow actually runs — RFC 9728 discovery, client identification, PKCE, resource indicators — and which agent SDKs can run it.
- [[mcp-sdk] excluding tool '<name>' from tools/list: invalid x-mcp-header declaration](https://zuplo.com/learn/mcp/errors/excluded-tool-invalid-x-mcp-header.md): Your MCP tool is missing from tools/list and no error was returned: one malformed x-mcp-header annotation makes conforming clients drop it, logging only a warning. The constraint it broke, and the fix.
- [Authorization with the MCP server failed](https://zuplo.com/learn/mcp/errors/oauth-completes-but-no-token-sent.md): The client reports connected but your MCP server sees no credential, or rejects the one it gets. Fix the redirect stripping Authorization, or the audience.
- [Couldn't reach the MCP server](https://zuplo.com/learn/mcp/errors/mcp-server-works-in-claude-code-but-not-claude-ai.md): claude.ai calls your MCP server from Anthropic's network, so DNS, a WAF rule, or a redirect can kill it while curl and Claude Code both succeed. Find the hop.
- [Dynamic Client Registration not supported](https://zuplo.com/learn/mcp/errors/dynamic-client-registration-not-supported.md): Your authorization server offers no way to get a client_id, so the MCP client stops before /authorize. Pre-register it — the steps per identity provider.
- [Failed to fetch authorization server metadata from all attempted URLs](https://zuplo.com/learn/mcp/errors/failed-to-fetch-authorization-server-metadata.md): The client knows which authorization server to use but cannot read its metadata, so OAuth stops before /authorize. The fix per SDK, identity provider, and client.
- [MCP headers config ignored when server has OAuth discovery](https://zuplo.com/learn/mcp/errors/configured-headers-ignored-when-oauth-discovery-present.md): Your MCP client found OAuth discovery metadata and started a token flow instead of sending the Authorization header you configured. The fix per client.
- [mcp_authentication_failed_error](https://zuplo.com/learn/mcp/errors/mcp-authentication-failed-error-managed-agents.md): Managed Agents matches vault credentials by normalized URL. A different path, subdomain, or non-default port sends no credential at all — so the 401 is correct.
- [ModuleNotFoundError: No module named 'mcp.server.fastmcp'](https://zuplo.com/learn/mcp/errors/no-module-named-mcp-server-fastmcp.md): The MCP Python SDK 2.0.0 removed mcp.server.fastmcp and renamed FastMCP to MCPServer, so an unbounded mcp requirement breaks on import. Pin or migrate.
- [resource indicator is missing, or unknown](https://zuplo.com/learn/mcp/errors/resource-indicator-missing-or-unknown.md): The authorization server returns invalid_target because the RFC 8707 resource parameter is missing, unknown, or mismatched. The fix per identity provider, SDK, and client.
- [Resource server does not implement OAuth 2.0 Protected Resource Metadata.](https://zuplo.com/learn/mcp/errors/401-without-www-authenticate.md): Your MCP server returns 401 but carries no resource_metadata pointer, so discovery never starts. The cause and fix in each SDK and gateway.
- [The request signature we calculated does not match the signature you provided](https://zuplo.com/learn/mcp/errors/aws-signaturedoesnotmatch.md): AWS recomputed your SigV4 signature and got a different value, so the MCP server never ran. Find which element differed, per signer and per hop.
- [Token audience validation failed](https://zuplo.com/learn/mcp/errors/token-audience-validation-failed.md): Your MCP server rejects a valid, signed token because its aud claim names something else. What each authorization server puts in aud, and how to match.
- [Your MCP server returns a login page or 403 instead of 401](https://zuplo.com/learn/mcp/errors/302-redirect-instead-of-401.md): Platform auth gates answer unauthenticated MCP clients with a browser login redirect instead of a 401, breaking the connection. The cause and fix on each platform.
- [Discovery — MCP glossary](https://zuplo.com/learn/mcp/glossary/discovery.md): How a client finds out where to authenticate, starting from a 401 it did not expect.
- [Transport and headers — MCP glossary](https://zuplo.com/learn/mcp/glossary/transport.md): How MCP messages travel, and the headers the 2026-07-28 revision added, changed, or dropped.
- [Credentials and registration — MCP glossary](https://zuplo.com/learn/mcp/glossary/credentials.md): How a client obtains a client identity and an access token before it calls anything.
- [Authorization and tokens — MCP glossary](https://zuplo.com/learn/mcp/glossary/authorization.md): What a server checks on the token it receives, and what it must refuse to do with it.
- [Protocol surface — MCP glossary](https://zuplo.com/learn/mcp/glossary/protocol.md): The primitives a server exposes, the shape of a result, and the error codes MCP defines.
- [Versions and governance — MCP glossary](https://zuplo.com/learn/mcp/glossary/governance.md): How revisions are numbered, how features are retired, and how any of it changes.
- [claude.ai, Claude Desktop, mobile, and Cowork connectors](https://zuplo.com/learn/mcp/compatibility/clients/claude-connectors.md): One hosted runtime backs all four surfaces, and it connects from Anthropic's infrastructure rather than from the reader's machine — which is why DNS, redirect, and firewall behavior differ from every local client here.
- [ChatGPT connectors and apps](https://zuplo.com/learn/mcp/compatibility/clients/chatgpt-connectors.md): The strictest of the two big chat hosts on credentials: user-consented OAuth or nothing. Streamable HTTP is required, and ChatGPT prefers a client ID metadata document over dynamic registration.
- [Claude Code](https://zuplo.com/learn/mcp/compatibility/clients/claude-code.md): The most configurable client here on every axis except protocol revision: four transports, its own client metadata document, flags for a client ID and callback port, an override for the discovery chain, and a command hook that generates headers at connection time.
- [Claude Agent SDK](https://zuplo.com/learn/mcp/compatibility/clients/claude-agent-sdk.md): Same engine as Claude Code without the browser, so authorization is headers only in practice. Server status is observable per server, which is how you find out a token expired.
- [Claude Managed Agents](https://zuplo.com/learn/mcp/compatibility/clients/claude-managed-agents.md): Credentials live in a vault keyed by server URL, in one of two shapes: a static bearer token, or an OAuth access token with an optional refresh block. The agent declares servers; the session supplies credentials.
- [Messages API MCP connector](https://zuplo.com/learn/mcp/compatibility/clients/messages-api-mcp-connector.md): The thinnest Anthropic client by design: tool calls only, one bearer token per server, and no local servers. Anthropic documents that you obtain and refresh the token before the API call.
- [OpenAI Responses API mcp tool](https://zuplo.com/learn/mcp/compatibility/clients/openai-responses-api.md): A bearer-token relay rather than an OAuth client, and the one client here that accepts the legacy HTTP+SSE transport without calling it deprecated.
- [Microsoft Copilot Studio](https://zuplo.com/learn/mcp/compatibility/clients/copilot-studio.md): Streamable HTTP only, and the connector path wants Microsoft's own protocol marker in the OpenAPI document. Generative orchestration has to be on before MCP works at all, and it caps an agent at 128 tools.
- [Codex CLI](https://zuplo.com/learn/mcp/compatibility/clients/codex-cli.md): Two kinds of server, a local process or an address, with per-server tool allowlists and short default timeouts: 10 seconds to start a server and 60 seconds for a tool call.
- [Gemini CLI](https://zuplo.com/learn/mcp/compatibility/clients/gemini-cli.md): The strictest `resource` behavior after Zed: Gemini CLI derives the value from the server URL rather than from protected resource metadata, so it sends it even when your server publishes none. It also rewrites tool names aggressively, forcing an `mcp_` prefix and truncating at 64 characters.
- [Cursor](https://zuplo.com/learn/mcp/compatibility/clients/cursor.md): Cursor's own table lists all three transports with no deprecation note on SSE, and marks the two HTTP transports as OAuth-capable. Variable interpolation works in the command, arguments, environment, URL, headers, and auth fields.
- [VS Code and GitHub Copilot](https://zuplo.com/learn/mcp/compatibility/clients/vs-code.md): VS Code negotiates the transport for you: it tries the HTTP stream transport and falls back to SSE. It also accepts two transports nothing else here does, a Unix socket and a named pipe, and it caps a request at 128 tools.
- [Devin Desktop, legacy Cascade agent](https://zuplo.com/learn/mcp/compatibility/clients/devin-desktop-cascade.md): This is the client most people still call Windsurf. It runs OAuth on all three transports, interpolates environment variables and file contents into configuration, and caps the agent at 100 tools.
- [Devin CLI](https://zuplo.com/learn/mcp/compatibility/clients/devin-cli.md): The current default agent in Devin, and the only client here that lets you turn the `resource` parameter off. Configuration reads from three tiers, with the gitignored local file first.
- [Zed](https://zuplo.com/learn/mcp/compatibility/clients/zed.md): The strictest RFC 8707 behavior in this matrix: source appends `resource` to the authorization URL, the token exchange, and the refresh, unconditionally. Zed follows the specification's registration priority, preferring a metadata document and falling back to dynamic registration.
- [JetBrains AI Assistant](https://zuplo.com/learn/mcp/compatibility/clients/jetbrains-ai-assistant.md): The authorization row is unknown end to end, and that's the finding rather than a gap in our research: the MCP page documents no authentication mechanism at all.
- [MCP Inspector 2.0.0](https://zuplo.com/learn/mcp/compatibility/clients/mcp-inspector.md): Released the same day as the `2026-07-28` revision, as one package with a web, CLI, and terminal client. It's the reference client for the current revision and the only one here that drives the tasks extension.
- [mcp-remote 0.1.38](https://zuplo.com/learn/mcp/compatibility/clients/mcp-remote.md): The bridge that retrofits OAuth onto a client that lacks it, by presenting a remote server over stdio. Its `--transport` flag chooses which HTTP transport to try first, and it keeps a separate token cache per combination of URL, resource, and headers.
- [MCP TypeScript SDK 1.29.0](https://zuplo.com/learn/mcp/compatibility/clients/typescript-sdk-1x.md): The 1.x line is where most frameworks and agents actually sit. Two of its cells explain a whole class of support tickets: `resource` is conditional on protected resource metadata, and there's no issuer validation at all.
- [MCP Python SDK 1.29.0](https://zuplo.com/learn/mcp/compatibility/clients/python-sdk-1x.md): More permissive than the TypeScript 1.x line on two cells: it sends `resource` unconditionally and takes a metadata document URL directly. It still performs no issuer validation.
- [MCP TypeScript SDK 2.0.0](https://zuplo.com/learn/mcp/compatibility/clients/typescript-sdk.md): Any framework that delegates MCP to this SDK inherits its revision. Note that the default is still the 2025-era protocol even at 2.0.0 — the version number and the wire revision move independently.
- [MCP Python SDK 2.0.0](https://zuplo.com/learn/mcp/compatibility/clients/python-sdk.md): The two reference SDKs made opposite default choices at version 2.0.0, and this is the half that defaults to the current revision. It's also the only row here with a yes in the issuer-validation column.

## Features

- [API Observability](https://zuplo.com/features/api-observability.md): Real-time logs and analytics for every request through your gateway. Searchable, filterable, exportable — with consumer-level attribution and integrations into your existing stack.
- [Authentication](https://zuplo.com/features/authentication.md): API keys, JWT, OAuth 2.0, OpenID Connect, mutual TLS, and TypeScript-based custom auth — composable per route, edge-validated, no SDK to install.
- [Backends & Resilience](https://zuplo.com/features/backends.md): Workload identity federation, Azure AD, mTLS, secure tunnels, retries, timeouts, and a circuit breaker — all running at the edge across 300+ data centers.
- [API Caching](https://zuplo.com/features/caching.md): Edge response caching, semantic cache for AI workloads, and CDN-aware Cache-Control headers — all configured per route, no Redis cluster to operate.
- [Rate Limiting](https://zuplo.com/features/rate-limiting.md): Per-IP, per-API-key, per-tenant, and per-token rate limits at the edge — plus monthly quotas. Programmable in TypeScript, configurable in JSON, enforced before traffic touches your origin.
- [API Key Management](https://zuplo.com/features/api-key-management.md): Hashed-at-rest, edge-replicated API keys with self-serve issuance, rolling rotation, custom metadata, and GitHub leak detection — validated in single-digit milliseconds across 300+ data centers.
- [API Security](https://zuplo.com/features/api-security.md): Multi-method authentication, schema validation, rate limiting, bot protection, and workload identity federation to your backends — all enforced in one edge runtime, in 300+ data centers.
- [API Monetization](https://zuplo.com/features/api-monetization.md): Subscriptions, plan-scoped API keys, real-time metering, soft and hard quotas, and a self-serve pricing page — everything you need to bill for an API, in one policy on every route.
- [Developer Portal](https://zuplo.com/features/developer-portal.md): Auto-generated docs from OpenAPI, interactive API explorer, self-serve API keys, custom React pages, and your custom domain — built into every Zuplo project, hosted for you.
- [GraphQL](https://zuplo.com/features/graphql.md): Put your GraphQL endpoint behind Zuplo — depth and complexity limits, introspection control, operation-aware analytics, a one-line GraphQL-to-MCP server, and a schema-aware playground. The same gateway as your REST APIs.
- [GitOps](https://zuplo.com/features/gitops.md): Your gateway is files in your Git repo. Every push deploys atomically. Every PR gets a preview URL on the global edge. Every revert is a `git revert`.
- [Testing](https://zuplo.com/features/testing.md): The same test suite runs against local dev, a real per-branch preview deployment, and production — one command, one `--endpoint` flag. `zuplo test` ships with the CLI on every plan; tests are plain TypeScript in your repo, next to the config they test.
- [Unlimited Environments](https://zuplo.com/features/unlimited-environments.md): Every Git branch is a real environment on the global edge — production, staging, feature previews, per-developer working copies. Three stages, three env-var scopes, no per-environment licensing, on every plan.
- [Multi-Cloud Gateway](https://zuplo.com/features/multi-cloud.md): Run Zuplo on managed edge, single-tenant dedicated (Akamai, AWS, Azure, GCP, Equinix), or self-hosted Helm on any Kubernetes — all behind one control plane. Reach private backends with WireGuard tunnels, PrivateLink, mTLS, AWS IAM, Azure AD, and GCP IAM.
- [Global High Performance](https://zuplo.com/features/global-high-performance.md): Deploy to 300+ edge locations in under 20 seconds. Sub-50ms latency worldwide, a 99.999% uptime SLA, and zero infrastructure to manage.
- [API Governance](https://zuplo.com/features/api-governance.md): Shared policies and Composite Inbound bundles applied to every route — auth, rate limits, schema validation, audit logging — enforced in CI before merge. SOC 2 Type II, immutable account audit logs, RBAC, fine-grained API key scopes.
- [MCP Server](https://zuplo.com/features/mcp-servers.md): Turn any OpenAPI spec into a remote MCP server in your gateway — tools, resources, and prompts derived from your existing routes. Streamable HTTP, edge-deployed, with the same OAuth, API keys, rate limits, and audit logging as your APIs.
- [OpenAPI Support](https://zuplo.com/features/open-api.md): Zuplo's gateway config IS an OpenAPI document. Routes, policies, request validation, the developer portal, and exported client SDKs all derive from one spec. OpenAPI 3.0/3.1, YAML or JSON, with overlays for environment-specific config and edge-enforced validation.
- [Programmable Gateway](https://zuplo.com/features/programmable.md): Custom inbound policies, outbound policies, and request handlers in typed TypeScript. Web-standard APIs (Fetch, Crypto, Streams), V8 isolates across 300+ POPs. Compose other routes with context.invokeRoute, share state via context.custom — no proprietary DSL, no separate Lambdas.
